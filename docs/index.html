三个样章，报告可点开核对

每篇都由完整流水线生成，指标自动摘自各自的 validation.md。

诚实口径：PASS 指三个样章各自的 validation.md 结构终检结果（样章级，非全文翻译完成度）；数量一致不等于语义无误；篇幅比达标不等于没有概括删减。演示动画为基于样章的流程编排，非实时翻译过程。

它是怎么做到的：九个阶段（Phase A–I）流水线与八项终检
Phase A–C
环境体检 · 解析 + 来源审计
pymupdf4llm / Marker / MinerU 解析 PDF，清点区块、公式、表格、图片，生成 manifest。
Phase D
术语表
先抽取关键术语并定译，全文统一，避免同一个概念前后翻得不一样。
Phase E
内容冻结 + 分块
LaTeX / 代码 / URL / DOI / 数字冻结为 [[IMM_…]] token，表格注册为表格任务，全文切块并加隐藏块 ID。
Phase F–G
逐块翻译 · 表格逐格
正文按块交给 agent 翻译；表格按单元格生成翻译任务，数值格标记保护。
Phase H
确定性组装
按 manifest 清单把译文与 token 原样装回，不经过模型手；表格模板逐格回填。
Phase I
八项终检
八项确定性检查全部通过才输出，任一失败给出可定位的修复任务。
  • 区块序列一致（逐块对应，无漏译/增删）
  • 标题层级与数量一致
  • 表格结构逐格一致，保护数值原样
  • 图片数量与引用完整
  • LaTeX 公式逐条一致（原文 token 还原）
  • 代码块 / URL / DOI 不被改写
  • 中英篇幅比在合理区间（防概括删减）
  • 残留 token / 占位符清零

    

  


  

    使用方法与依赖
    

      
    
        
  1. 把论文 PDF 放进一个目录，运行 prepare_paper.py 完成解析、审计与分块；
    2. 
        
  2. 在有 agent 能力的 CLI（本项目用 Codex CLI）里逐块翻译正文、按单元格翻译表格；
    3. 
        
  3. 运行 assemble_markdown.py 确定性组装，再跑 validate_markdown.py 终检；
    4. 
        
  4. 终检 PASS 后得到 <论文>_中文.md，可直接放进 Obsidian / 任何 Markdown 阅读器。
    5. 
      

      
# 1) 安装 PDF 解析依赖（与 Skill 安装分开；三选一，最轻量起步）
pip install pymupdf4llm
# 2) 解析 + 结构审计（默认输出 work/<论文名>/；长论文可加 --pages 1-3 试点）
python scripts/prepare_paper.py paper.pdf --project-root .
# 3) 翻译：在 Codex CLI 中按 chunks/ 逐块翻译、按单元格填表格任务
python scripts/assemble_markdown.py work/paper/chunks/manifest.json
# 4) 终检（八项守门）
python scripts/validate_translation.py --manifest work/paper/chunks/manifest.json --source work/paper/source/source_clean.md --translated work/paper/paper_中文.md --report work/paper/validation.md

      
# 本站预览（纯静态，无构建步骤）：在项目根目录运行
python -m http.server 8000   # 然后打开 /docs/ ；样章阅读页在 /docs/samples/
# 阅读页/下载包由 scripts/build_site.py 从 demo/ 产物生成：
python scripts/build_site.py && python scripts/check_site.py
# 调试/录制动画时可直接跳转到任意时刻：
docs/player.html?t=21        window.demo.seek(21)
